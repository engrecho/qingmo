# README 截图说明

截图使用轻墨真实渲染器，公开演示文档位于 `docs/examples/`。不会读取用户文件、应用会话或诊断日志，也不会修改安装在应用程序文件夹中的轻墨。

## 重新生成

在仓库根目录运行：

```bash
npm --prefix dev run build:renderer
env -u ELECTRON_RUN_AS_NODE dev/node_modules/.bin/electron dev/scripts/capture-readme.js --no-sandbox --disable-gpu
```

Windows 终端运行前清除 `ELECTRON_RUN_AS_NODE`，然后执行 `dev\node_modules\.bin\electron dev/scripts/capture-readme.js`。实际像素尺寸与主机显示比例、工作区高度有关。

## 三张截图

- `docs/assets/writing-light.png`：浅色分栏、打开的文档与标题大纲。
- `docs/assets/preview-edit.png`：纯预览开启直接编辑；脚本真实输入一段文字，并断言已经同步到 Markdown。
- `docs/assets/reading-dark.png`：通过工具栏切换到深色纯预览，关闭文件侧栏和大纲。

脚本使用隔离的临时 userData，通过真实工具栏按钮切换状态，不覆盖页面样式或拼造界面。截图生成后会销毁独立窗口并清理临时会话。图片为真实 capturePage 输出，未叠加虚构功能或性能数据。

README 中新功能以当前源码为准；下载版本以 GitHub Release 的实际发布内容为准。更新截图前先验证功能，再调整演示文案，避免让界面图与产品行为不一致。

## README 动态演示

首屏 `docs/assets/writing-intro.gif` 来自用户上传的 `生成M形图片.mp4`，仅作视觉介绍，不是应用操作录像。源视频约 10 秒、720×720；转换为 320×320、8 fps 循环 GIF，移除音轨，避免将视频和临时帧重复提交仓库。

使用 FFmpeg 转换（将输入路径替换为原视频路径）：

```bash
ffmpeg -i '生成M形图片.mp4' -filter_complex_threads 1 \
  -filter_complex '[0:v]fps=8,scale=320:-1:flags=lanczos,split[a][b];[a]palettegen=max_colors=64[p];[b][p]paletteuse=dither=bayer:bayer_scale=4' \
  -loop 0 docs/assets/writing-intro.gif
```

三个功能 GIF 由 `dev/scripts/capture-readme-gifs.js` 自动录制真实渲染器。需要 FFmpeg 和可用显示环境。在仓库根目录执行：

```bash
npm --prefix dev run build:renderer
env -u ELECTRON_RUN_AS_NODE dev/node_modules/.bin/electron dev/scripts/capture-readme-gifs.js --no-sandbox --disable-gpu
```

无桌面的 Linux 需要先启动 Xvfb 并设置 `DISPLAY`。`--no-sandbox` 仅用于当前隔离云环境，正常桌面环境可省略。输出为 960 像素宽、8 fps 的循环 GIF：

- `live-preview.gif`：通过真实编辑器输入标题与列表，断言右侧预览出现对应内容与标题结构。
- `theme-switch.gif`：点击真实主题按钮，断言浅色→深色→浅色的状态变化。
- `preview-edit.gif`：在分栏视图右侧预览直接输入文字，断言完整 Markdown 文档与左侧编辑器均同步更新。

录制在隔离临时 userData 中执行，不读取用户会话；PNG 帧仅暂存于系统临时目录，成功或失败均清理。GIF 的固定帧率用于阅读演示，不是实际输入延迟或性能测量。仅更新说明与演示资源，无需重新生成安装包。
